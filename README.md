# fengshui-shushu（术数研判）

**中文** | [English](README.en.md)

一个给 Claude 用的 **Skill**，让它按传统术数的规矩回答风水、命理类问题。

不是"占卜 App"，也不是把某本书抄成的数据库。它是一份**结构化的方法论说明书**：把散落在《八宅明镜》《小六壬掐指神通术》《五格剖象法》等公开术数体系里的规则，整理成可查、可复算、有纪律的形式，并强制 Claude 按固定骨架回答，而不是随口发挥。

## 它解决什么问题

直接问 AI"我家财位在哪"，常见的毛病是：给一个模糊结论、不说依据、不列算式、随口讲得玄而又玄、顺带制造焦虑。

这个 Skill 针对性地固化了四件事：

1. **分类再动手** —— 先判断你问的是"看环境 / 起卦 / 看人 / 问身心"哪一类，走不同路径，不混着讲。
2. **推算必须列算式** —— 命卦要写出 `1+9+8+5=23 → 2+3=5 → 11−5=6 → 乾命`，起课要列出三次掐算过程，笔画要说明康熙口径。你能核，它就不能糊弄。
3. **固定回答骨架** —— 定盘 → 落点 → 具体动作 → 边界。不许停在"注意调整一下床位"，必须落到"床头转到东南"。
4. **几条纪律** —— 不吓人、不制造焦虑、不推销；象数疗法与道医必须先建议就医、不推荐停药、不替代诊疗。

## 跨平台使用

这套内容不只给 Claude 用。`build.py` 从**单一源文件**生成各平台需要的格式：

```bash
python3 build.py           # 生成全部产物到 dist/
python3 build.py --check   # 只检查源文件是否齐全
python3 build.py --list    # 列出会生成哪些文件
```

产物对应关系：

| 平台 | 产物 | 说明 |
|---|---|---|
| Claude（推荐） | 直接放 `SKILL.md` + `references/` | 支持按需加载，最省上下文 |
| Claude（save_skill / 手动） | `dist/claude-single-file.md` | 单文件全量版，因为 save_skill 只接受单文件 |
| Codex CLI | `dist/AGENTS.md` | Codex 自动读取仓库根目录的 AGENTS.md |
| Gemini CLI | `dist/GEMINI.md` | —— |
| Windsurf | `dist/.windsurfrules` | —— |
| Cursor | `dist/.cursor/rules/fengshui-shushu.mdc` | 带 frontmatter 规则声明 |
| 上下文有限的模型（网页版 DeepSeek / Kimi 等） | `dist/system-prompt-compact.md` | 只含主干，约完整版的 6.5% |

**为什么有精简版**：网页版模型装不下完整内容（约 1770 行），硬塞会挤掉用户自己的问题。精简版保留主干规则和纪律，细节让用户按需查询。

**工作流**：改内容 → 改 `SKILL.md` 或 `references/` → 跑 `build.py` → 各平台产物自动更新。**不要手动编辑 `dist/` 里的文件**，它们会被覆盖。

`dist/` 默认已加入 `.gitignore`（产物不入库）。如果你想让某些平台的产物随着仓库发布，把对应条目从 `.gitignore` 里去掉即可。

## 案例库（这个项目最有价值的部分）

规则谁都能抄，**案例才是真正值钱的东西**。

真实问题很少是单条规则能答的——往往吉凶交织、信息不全、几个条件互相打架。那种时候靠的是"先看谁、后看谁、哪个优先"的经验，而这只能从案例里长出来。

`references/cases/` 存的正是这个，并且记录了三样别处没有的东西：

- **当时的犹豫** —— 哪一步没把握、哪个信息缺失导致只能保守判断、两派说法不一致时选了哪派
- **不应验的记录** —— 只留"准的"会让案例库失去校准价值，变成一本自夸集
- **由此暴露的规则漏洞** —— 案例里用到某条 references 没写的推法时，会标注出来并回填

填写的模板见 `references/cases/TEMPLATE.md`，建议在你自己的使用中持续积累。

## 安装

这个 Skill 面向支持 Skill 机制的 Claude 客户端（如 Claude 桌面端）。

**方式一（推荐）**：把整个 `fengshui-shushu/` 目录放进你的 skills 目录。

**方式二**：在 Claude 桌面端用 `save_skill` 载入——`SKILL.md` 作为主体，`references/` 下的五份文件作为附件一并保留。

**方式三（手动）**：`SKILL.md` 是一份自包含的完整文档，五份 references 的内容已按附录形式并入其中。如果你只想用单文件版本，直接拿 `SKILL.md` 就能工作，不需要额外文件。

## 使用

安装后有两种调用方式：

**自动触发** —— 直接问，Claude 会判断是否加载。例如：

- "我 1985 年生，房子 2019 年入住，大门朝东南，主卧在西北，这样行不行？"
- "帮我起一卦，问这次面试成不成"
- "我叫李XX，这个名字怎么样"
- "今天该穿什么颜色？"

**点名调用** —— 在输入框输入 `/fengshui-shushu`，后面跟问题。

### 提问建议

信息给全，答案质量差一个档次：

- **看风水**：至少给"入住年份 + 大门朝向（坐向）"，有户型图和楼层更好
- **起卦问事**：一句话说清"具体问什么"，别问"我最近怎么样"这种
- **看姓名**：全名 + 出生年份
- **每日配色**：直接给日期即可

## 关于来源

内容取自**传统公开术数体系**——八宅明镜、小六壬（掐指神通术）、五格剖象法、象数疗法、传统道医养生等。这些都是流传数百年的公开知识，不属于任何单一作者或出版物。

本仓库**不包含**任何现代出版物的正文内容，也不提供任何付费作品的全文。如果某本现代读物（例如各类网络小说或出版物）在讲解这些术数时形成了独到的判断窍门或口诀，那部分内容需要由使用者自己从合法渠道获得并补充。

## 扩展方式

想往里加东西，按分类加到对应文件，不要全塞进 `SKILL.md`（主干要短，references 按需加载）：

- 新的风水流派或飞星细则 → `references/bashuxiang.md`
- 更多断辞、案例、应期规律 → `references/xiaoliuren.md`
- 笔画表、更多数理注解 → `references/xingming.md`
- 识人经验、新象的读法 → `references/shiren-xiangshu.md`
- 化解物、养生要诀 → `references/huajie-daoyi.md`
- **新增一整个术数体系** → 新建 `references/xxx.md`，并回到 `SKILL.md` 的"参考文件"一节加一行索引

如果你改的是已经安装的 Skill，注意**编辑本地文件不会自动生效**，需要重新载入。
