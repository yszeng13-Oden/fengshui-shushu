# 案例库

规则谁都能抄，**案例才是这个 skill 真正值钱的部分**。

前面五份 reference 写的全是"怎么算"。但真实问题很少是单条规则能答的——往往是吉凶交织、信息不全、几个条件互相打架。那种时候靠的是"先看谁、后看谁、哪个优先"的判断经验，而这只能从案例里长出来。

## 怎么用这个库

**回答问题时**：如果用户的情况和某个案例结构相似（同样是"门凶卧吉"、同样是"土月缺水"、同样是"问事落空亡"），**先读那个案例**，照着它的推演顺序走，再套到用户的具体数字上。这比凭空组织规则稳得多。

**不要生搬结论**。案例的结论只对它的那组输入成立。你借的是**推演路径和判断分寸**，不是答案。

## 怎么往里加案例（用户提供素材时）

用户讲一个真实问题后，按 `TEMPLATE.md` 的结构整理成一个新文件放进本目录。**有几个纪律**：

**必须记推演过程，不能只记结论**。只写"最后建议床头朝东南"是废的；要写"为什么先看门再看床、为什么没动卫生间"。

**必须记"当时犹豫了什么"**。这一栏最有价值——它记录的是判断的边界在哪。

**拿不到的信息要标明**。写"用户没给楼层，按普通楼层处理"，别假装算全了。

**应验与不应验都要记**。只留"准的"会让整个库失去校准价值，变成一本自夸集。用户后来反馈不准的，照样归档，并在结论里标明偏差。

## 文件命名

用 `编号-主题.md`，编号三位递增：

```
cases/
├── README.md            （本文件，用法说明）
├── TEMPLATE.md          （模板，复制它来新建）
├── 001-门凶卧吉.md
├── 002-土月问事落空亡.md
└── ...
```

主题用**问题结构**命名，不要用具体人名地点——"门凶卧吉"比"张先生家"有用得多，因为前者能被检索到。

## 案例与规则冲突时怎么办

如果某个案例的推法和你从 references 里读到的规则矛盾，**以案例为先，但要标注出来**——那说明规则写得不够细，需要回来把 reference 补上。案例库的一个副作用就是帮你发现规则文档的漏洞。发现矛盾时提醒用户一次。
